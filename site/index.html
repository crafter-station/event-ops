event-ops

After your event, every guest who came gets exactly one credit code by email.

Run it from your terminal or hand it to your coding agent.

  • Zero dependencies
  • Guests from Luma or a CSV
  • Sends with Resend or a mail merge

One binary for every step of event night

          
Every command prints JSON when piped or with --json, so an agent can drive it. Commands that write stay in dry run until you pass --commit or --confirm.

        

        

          

            
CommandWhat it does

            
              
event-ops credits init <event> [--luma-event-id evt_…] [--require checked-in,feedback] [--target luma|chatgpt]Creates the event ledger with its rules and delivery target.

              
credits sync [--csv guests.csv]Pulls guests from the Luma API with LUMA_API_KEY. On free plans, merge a Luma CSV export instead.

              
credits import guests|feedback|codes <file> [--reserve N]Merges a guest export, a feedback export or an OpenAI credits CSV. --reserve holds codes back for replacements.

              
credits statusPrints counts, pool stats and possible duplicates such as Gmail aliases or shared ChatGPT emails.

              
credits assign [--commit]Plans one code per person who qualifies. Writes only with --commit.

              
credits burn <email|code>Retires a broken code and assigns a fresh one, from unused codes first and then the reserve.

              
credits export [--out file] [--mark-sent]Writes a mail-merge CSV of unsent codes. With --mark-sent, the next run skips what already went out.

              
credits send --from … --subject … [--confirm]Sends one email per code through Resend. Shows a preview until you pass --confirm.

              
triage <guests.csv>Ranks a Luma guest export for the last open spots, using GitHub and web evidence.

              
skills list|get <name>Prints a bundled skill for your agent, such as credits or triage.

              
events list|use <slug>Lists event ledgers and switches the active one.

              
schemaDescribes every command and flag in JSON for agents.

              
demoRuns the full flow offline with made-up data.

            
          

        

      

    


    

      

        

          
Codes go out by email after the doors close

          
A live claim page can fail on venue Wi-Fi and invites fake emails. event-ops sends each code to the inbox the guest registered with.

        

        
    
          
  1. 
            
    Volunteers scan with Luma
    
            
    Door volunteers use Luma's own check-in role. They see tickets, and the check-in time lives in one place.
    
          
    2. 
          
  2. 
            
    The inbox proves who they are
    
            
    The code lands where the guest registered, so a stranger has nothing to claim.

  3. 
            
    The ledger is a local file
    
            
    You give out and send codes after the event, from your laptop, on any connection.
